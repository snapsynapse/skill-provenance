# Release provenance

Updated: 2026-09-23

## Purpose

This document classifies release surfaces before checksum or identity
attestation is added. It does not make `MANIFEST.yaml` a signature or trust
anchor. Publisher identity, bundle integrity, and runtime safety remain
separate claims.

## Artifact classes

| Surface | Class | Stable identity | Verification boundary |
|---|---|---|---|
| Tagged `skill-provenance/` directory | Canonical authored bundle | Exact Git tag and tree | Run the tagged `validate.sh`; compare the tag with the intended release |
| `skill-provenance.skill` | Stable portable release asset | Release tag, asset name, and SHA-256 digest | Compare archive inventory with the canonical bundle and verify its digest |
| `build/strict/skill-provenance/` | Derived transport | Canonical source tag plus packaging procedure | Rebuild with `package.sh strict` and validate the derived manifest |
| `build/clawhub/skill-provenance/` | Derived registry transport | Canonical source tag plus packaging procedure | Rebuild with `package.sh clawhub`; registry state is a separate publication record |
| `verify.sh` | Tagged repository entry point | Exact Git tag and pinned canonical-validator digest | Inspect the wrapper and validate its pinned digest before execution |
| `action.yml` | Tagged repository entry point | Exact Git tag or immutable commit | Inspect the composite action and its delegated validator at that ref |
| ClawHub listing | Separately published registry copy | Registry version and publication record | Reconcile with the canonical source; do not assume it matches GitHub |

ClawHub package contents are determined by `package.sh`. ClawHub-generated
metadata such as a skill card is registry-owned and is not part of the
canonical authored bundle.

## Future identity-chain design

Before adding keyless signing or GitHub artifact attestations:

1. Decide whether the stable subjects are the canonical tagged tree, the
   `.skill` asset, or both.
2. Generate checksums from the release workflow, not from an unrelated local
   build.
3. Bind each attestation to the artifact digest, repository, workflow identity,
   and release ref.
4. Verify the published result from a clean temporary download.
5. Keep consumer guidance explicit that publisher identity does not establish
   skill safety.

Detached signatures for derived transports remain a later roadmap item unless
those transports become intentionally published release assets.
